# FlexConnect 功能验证指南

## 文档目的

本文档用于验证 FlexConnect 的关键逻辑是否正确实现，特别关注：
- ✅ 上电默认模式设置和恢复逻辑
- ✅ 掉电恢复功能和优先级逻辑
- ✅ 恢复出厂设置功能
- ✅ 参数持久化和断电重启验证

## 验证前准备

### 硬件准备
- [ ] FlexConnect 硬件设备 × 1
- [ ] USB 转串口线 × 1（或设备已通过 USB 连接）
- [ ] 可控电源开关（用于断电重启测试）
- [ ] PC 或 UDISK 用于验证连接状态（可选）

### 软件准备
```bash
cd SmartUSBHub_Pro-4CH_USB2.0/library/smartusbhub_ng
pip install -r requirements.txt  # 如果还未安装依赖
```

### 初始状态确认
在开始测试前，先恢复出厂设置：
```bash
python examples/flexconnect_advanced_test.py
# 选择执行恢复出厂设置测试
```

## 常见问题排查

### 问题 1：断电重启后模式不正确

**可能原因：**
1. 参数未正确写入 Flash
2. 上电恢复逻辑错误
3. 优先级处理不正确

**排查步骤：**
```c
// 检查 smart_switch_params.c 中的逻辑
smart_switch_status_recover(0)
```

**检查点：**
- `channel_default_power_flag` 是否为 0？
- `poweroff_recover` 的值是多少？
- `flexconnect_default_mode` 是否正确？

### 问题 2：掉电恢复不生效

**可能原因：**
1. `poweroff_recover` 未正确设置
2. 按键切换时未保存状态
3. `channel_power_status` 未正确更新

**排查步骤：**
1. 确认 `get_auto_restore_status()` 返回 1
2. 检查 `smart_switch_gpio.c` 中按键逻辑是否调用 `smart_switch_params_write()`
3. 检查 Flash 写入是否成功

### 问题 3：恢复出厂设置后参数未恢复

**可能原因：**
1. `smart_switch_params_reset()` 逻辑错误
2. 默认值定义不正确

**排查步骤：**
```c
// 检查 smart_switch_params.c:179
void smart_switch_params_reset(device_params_t *params)
{
    // 检查这些值：
    default_params.poweroff_recover = 0;  // 应该是 0
    default_params.flexconnect_default_mode = FLEXCONNECT_MODE_PC;  // 应该是 MODE_PC
}
```

### 问题 4：优先级逻辑不正确

**检查点：**
```c
// smart_switch_params.c:227-275
// 优先级顺序应该是：
// 1. channel_default_power_flag = 1  → 最高优先级
// 2. poweroff_recover = 1 且有保存的状态 → 次优先级
// 3. flexconnect_default_mode → 最低优先级（兜底）
```
