# SmartUSBHub 压力测试指南

## 概述

`stress_test.py` 是一个全面的压力测试程序，用于测试 SmartUSBHub 多进程架构在各种并发场景下的稳定性和正确性。它可以模拟多种并发冲突场景，帮助发现潜在的问题。

## 功能特性

### 测试场景

1. **同一通道并发冲突** (`same_channel_conflict`)
   - 多个进程同时对同一个通道进行操作
   - 测试电源开关、数据线控制、电压/电流读取的并发冲突
   - 验证服务进程能否正确处理并发请求

2. **不同通道并发操作** (`different_channels`)
   - 多个进程同时对不同通道进行操作
   - 测试多通道并发访问的稳定性

3. **快速连续请求** (`rapid_requests`)
   - 快速连续发送大量请求，不等待响应
   - 测试请求队列积压和超时处理
   - 验证系统在高负载下的表现

4. **读写混合操作** (`read_write_mix`)
   - 同时进行读取和写入操作
   - 测试读写操作的并发安全性

5. **通道快速切换** (`channel_switching`)
   - 快速在不同通道之间切换操作
   - 测试通道切换时的状态一致性

6. **混合场景** (`mixed`)
   - 混合所有测试场景
   - 最接近真实使用场景的压力测试

## 使用方法

### 基本用法

```bash
# 使用默认配置运行混合场景测试
python stress_test.py

# 指定工作进程数和测试时长
python stress_test.py --workers 20 --duration 120

# 测试同一通道的并发冲突
python stress_test.py --test-type same_channel_conflict --workers 15 --duration 60

# 测试快速连续请求
python stress_test.py --test-type rapid_requests --workers 30 --duration 30
```

### 命令行参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `--workers` | int | 10 | 工作进程数量 |
| `--duration` | int | 60 | 测试持续时间（秒） |
| `--test-type` | str | mixed | 测试类型 |
| `--channel` | int | 1 | 测试通道（用于单通道测试） |
| `--iterations` | int | 1000 | 每个工作进程的迭代次数 |
| `--timeout` | float | 5.0 | 请求超时时间（秒） |

### 测试类型选项

- `same_channel_conflict`: 同一通道并发冲突
- `different_channels`: 不同通道并发操作
- `rapid_requests`: 快速连续请求
- `read_write_mix`: 读写混合操作
- `channel_switching`: 通道快速切换
- `mixed`: 混合所有场景（推荐）

## 测试示例

### 示例1: 高强度压力测试

```bash
# 30个工作进程，运行2分钟，混合场景
python stress_test.py --workers 30 --duration 120 --test-type mixed
```

### 示例2: 同一通道冲突测试

```bash
# 20个工作进程同时操作通道1，测试并发冲突处理
python stress_test.py --test-type same_channel_conflict --workers 20 --channel 1 --duration 60
```

### 示例3: 快速请求测试

```bash
# 50个工作进程快速发送请求，测试队列处理能力
python stress_test.py --test-type rapid_requests --workers 50 --duration 30 --timeout 3.0
```

### 示例4: 多通道并发测试

```bash
# 测试不同通道的并发操作
python stress_test.py --test-type different_channels --workers 16 --duration 90
```

## 测试报告

测试过程中会每10秒输出一次统计报告，包括：

- 总请求数
- 成功/失败请求数
- 成功率
- 错误类型统计（超时、运行时错误、冲突错误）

测试结束后会输出详细的最终报告，包括：

1. **总体统计**
   - 总请求数、成功数、失败数、成功率

2. **错误统计**
   - 超时错误、运行时错误、冲突错误的数量

3. **操作统计**
   - 每种操作的成功率和失败率

4. **通道统计**
   - 每个通道的操作数和冲突率

## 测试指标

### 关键指标

- **成功率**: 应该保持在 95% 以上（在正常负载下）
- **超时错误**: 应该很少，如果频繁出现可能表示队列积压
- **冲突错误**: 应该为 0（多进程架构应该避免冲突）
- **响应时间**: 通过超时设置间接测试

### 性能基准

在正常配置下（10个工作进程，60秒测试）：

- 总请求数: 通常 > 1000
- 成功率: > 95%
- 超时错误: < 5%
- 冲突错误: 0

## 故障排查

### 问题1: 大量超时错误

**可能原因**:
- 工作进程过多，请求队列积压
- 服务进程处理速度慢
- 超时时间设置过短

**解决方案**:
- 减少工作进程数
- 增加超时时间
- 检查服务进程是否正常

### 问题2: 冲突错误

**可能原因**:
- 多进程架构实现有问题
- 服务进程没有正确串行化请求

**解决方案**:
- 检查服务进程的请求处理逻辑
- 确保请求队列正确工作

### 问题3: 服务进程崩溃

**可能原因**:
- USB设备连接问题
- 服务进程异常处理不完善

**解决方案**:
- 检查USB设备连接
- 查看服务进程的错误日志
- 检查异常处理代码

## 注意事项

1. **设备连接**: 确保 SmartUSBHub 设备已正确连接
2. **资源限制**: 工作进程数不要过多，避免系统资源耗尽
3. **测试时长**: 建议至少运行60秒以获得有意义的统计结果
4. **中断测试**: 可以随时按 Ctrl+C 停止测试

## 与 run_all.py 的区别

| 特性 | run_all.py | stress_test.py |
|------|-----------|----------------|
| 用途 | 正常业务运行 | 压力测试 |
| 进程数 | 固定4个业务进程 | 可配置（默认10个） |
| 操作模式 | 正常业务逻辑 | 高强度并发测试 |
| 统计报告 | 无 | 详细的统计报告 |
| 测试场景 | 单一场景 | 多种并发场景 |

## 最佳实践

1. **渐进式测试**: 从小规模开始，逐步增加工作进程数
2. **多样化测试**: 运行不同类型的测试场景
3. **长时间测试**: 运行较长时间（>5分钟）以发现潜在问题
4. **监控资源**: 监控CPU和内存使用情况
5. **记录结果**: 保存测试报告用于对比分析
